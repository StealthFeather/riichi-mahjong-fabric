# 26.3.25：完整牌谱归档、回放与策略概率分析

正式版本号为 `0.4.2+fabric.26.3.25`。本版将完整对局归档、个人牌谱日历、牌桌回放和策略概率分析纳入正式功能，并修复终盘丢失已公开里宝牌展示的问题。保留 26.3.24 的中心风盘菜单、风牌名称，以及此前的三级四麻 AI、离线座位接替、手牌隐私、规则与显示修复；历史能力与验证记录见 [26.3.24 说明](26.3.24.md)。

## 安装与数据库

需要 Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.163.0+26.3、Java 25，以及运行服务端的账号可执行的 Node.js 22+。Polymer、固定版本 AI 源码和 MySQL JDBC 驱动已内嵌，不需要 npm 安装、GPU 或远程 AI 服务。仅服务端安装麻将 Mod，玩家使用原版客户端并接受既有 TimoryResource；本次更新不新增材质，不需要更换已包含麻将资产的资源包。

停服并备份后，用 `riichi-mahjong-0.4.2+fabric.26.3.25.jar` 替换旧版麻将 JAR，确保 `mods/` 中只有一个麻将版本，再正常开服。升级备份应同时包含世界、现有数据库、Mod 和配置，以便整体恢复。

牌谱模块读取 `config/timory_quest_server.json`，复用 Quest 已有的 MySQL 连接参数和时区。只读取这份配置，不重写连接设置，也不修改 Quest 的业务表。使用以下麻将专用表；已存在的表继续沿用：

| 表 | 内容 |
| --- | --- |
| `riichi_replays` | 完整牌谱、开始与结束时间、规则预设 |
| `riichi_replay_players` | 参赛玩家、座位、最终分数与名次 |
| `riichi_replay_analysis` | 按牌谱缓存的策略概率与实战选择结果 |

数据库账号需要具备这些专用表的创建和读写权限。数据库操作在有界后台队列执行；连接或写库失败时，完整记录先持久化到世界目录的 `data/riichi-replay-outbox/`，恢复后重试写入，成功后移除对应待传文件。不要通过删除待传文件处理连接故障。

## 自动记录与个人牌谱

开启完整记录的对局在**自然完成整场比赛**时自动归档，包含各局、按顺序接受的动作、手牌、摸牌、牌河、副露、牌山和结算状态。手动结束、重置或其他未完成的对局不会冒充完整牌谱。正常存档恢复可继续记录尚未结束的比赛；升级前未启用完整记录的对局无法补出缺失历史。

主手右键普通“牌谱”物品，打开玩家概况主页，进入“我的牌谱”。普通牌谱不再保存或加载桌面设置；预设练习牌谱保留固定场景加载功能。

牌谱日历参考 Quest 签到布局，按 Quest 配置时区和对局结束日期归档。有参与记录的日期显示红中，其余日期显示白板，物品名称显示对应日期，支持切换月份。只能查询自己参与的对局。

点击红中日期进入当日牌谱列表，按结束时间从新到旧排列，并支持分页。每行依次为：载入牌谱、东家分数、南家分数、西家分数、北家分数、发财分析开关；三麻未启用的北位显示占位信息。分数项附带参赛者信息，发财只切换该记录是否启用分析。

点击该行第一个物品载入记录，需要 8 格内有一张自己拥有的空闲牌桌，且没有其他真人在座。载入回放不覆盖目标桌库存、规则预设或座位设置；退出回放后可继续正常使用牌桌。

## 按视角控制回放

回放只恢复已经记录的历史状态，不重新运行机器人、不接受出牌或鸣牌决定。所有控制按钮位于选中视角牌河左右两侧，切换视角后随之移动，文字朝向该座位。显示、交互体和射线命中复用实战桌沿按钮的同一套实现，布局避开牌河、牌山和各座拔北牌。

左列：开局、上一局、上一巡、上一步、播放／暂停、下一步、下一巡。

右列：下一局、终局、倍速、视角、全部手牌显示、分析开关、退出回放。

“上一步／下一步”按动作帧移动；“上一巡／下一巡”跳到选中视角玩家的相邻出牌回合，略过他人动作，同一巡中的开杠、拔北与补牌不重复计巡。支持跨局和首尾边界，以及 0.5、1、2、4 倍速播放。

桌沿恢复显示当时合法的吃、碰、杠、立直、和牌与跳过等操作；启用分析后附上对应操作概率。历史操作按钮只供查看，不会提交动作、修改对局或改变原牌谱。

## 策略概率与实际出牌标记

分析复用现有麻将机器人评估。该 AI 原本是确定策略，没有原生概率输出；本版以明确的 softmax 模型构造**策略概率分布，不是 AI 原生概率，也不是胜率或经过统计标定的玩家选择频率**。四麻使用高级 AI 的可见信息评估并保留其防守推荐，三麻复用现有 Java 向听与可见进张评估及原机器人操作推荐。公式、温度和推荐优先规则见 [AI 策略模型](../ai/README.md#replay-policy-probabilities-cache-version-2)。

两类分布独立归一：

- 全部合法弃牌牌种的条件概率合计 100；同一种牌的普通弃牌与立直弃牌合并为一种牌面选择，赤五与普通五保持区分。
- 全部合法动作的概率另行合计 100；各个具体弃牌、立直、吃碰杠、和牌、跳过等按规则引擎的合法操作计算。桌沿立直按钮汇总所有合法立直弃牌的动作概率。

整数百分比采用最大余数法分配，避免分别四舍五入后合计偏离 100；单一选择可显示 100，不再设 99 分上限。手牌上每种弃牌选择显示一次概率，整数值低于 1% 的普通候选不显示数字。完整分布保留全部合法选择，排名按未取整概率计算。

选中视角只有一个历史实际选择箭头，并在箭头上方显示该牌概率，文字宽度与牌面一致：

- 实际选择达到最大策略概率：绿色。
- 实际选择排第二或第三：黄色。
- 其他实际选择：红色。

出牌前，箭头指向历史上实际选中的手牌；出牌后跟随到准确的河牌。该牌被吃、碰、杠拿走时，标记随原牌进入副露，加杠不会误标新增上层牌。原始河牌序号与赤牌身份保持区分。记录缺失、矛盾，或该次实际为杠、拔北、自摸时，不借用后续回合的弃牌。

“本局均值 X%”是该玩家实际弃牌策略概率的平均值，不是原来的决策质量评分。分析输入仍只包含本人手牌和当时公共信息，未来记录只用于事后识别实战选择，不参与 AI 评估。分析有独立的有界后台队列、Node 进程、超时和缓存，不占用实战机器人的工作进程。

## 旧记录与终盘显示兼容

已有数据库完整牌谱继续使用原格式，无需删除或迁移。分析缓存升级为版本 2，并标记 `modeled-softmax-v2`；旧 0–99 分缓存不会作为概率显示，启用分析后自动重算，原牌谱保持不变。

本版独立保存最后一手已公开的结算展示阶段。规则进入 `MatchEnded` 后，已公开里宝牌、赢家手牌和和牌张排版继续显示；实战存档恢复和旧数据库牌谱的终盘同样适用。规则阶段和可操作判断仍保持终盘状态，开始新局或重置时清除旧结算展示。

普通宝牌与赤五仍使用原版附魔光效。客户端光影或渲染设置可能改变光效可见性；本版修复的是终盘丢失最后结算展示的独立问题，不修改材质或添加服务端附魔替代方案。未公开的对局暗手牌面和光效仍仅向所属玩家发送。

## 验证范围

牌谱功能实现已通过 28 组 Java 回归、17 项 Node 测试及 22 项独立数据库检查，覆盖完整对局归档、恢复、概率守恒、旧缓存失效、实际非最优弃牌、三麻与四麻、逐巡跳转、被鸣牌身份、各朝向控件命中、拔北遮挡、概率字宽、箭头配色，以及终盘里宝和存档恢复。正式版构建哈希和检查结果以随发布附件提供的 `verification.json`、`replay-database-verification.json` 为准。

尚未完成本版真实客户端像素级画面、菜单交互或完整联机牌局验收；当前验证环境缺少可用的 GLX／Vulkan 图形驱动。原版 ItemDisplay 元数据编码与往返检查可验证光效组件发送，但不代替光影环境下的可见效果验收。

构建与测试入口为 `node build.cjs`、`node test.cjs`；独立数据库检查使用 `node test-replay-database.cjs /path/to/h2-2.3.232.jar`。构建或打包不会自动安装到正式服，依赖设置见 [BUILDING.md](../BUILDING.md)。

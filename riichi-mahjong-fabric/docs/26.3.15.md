# 0.4.2+fabric.26.3.15 · 四麻分级 AI

基于上一正式发布 `v0.4.2+fabric.26.3.14`，提交 `1faae0d4abc56c1d2ba87bb77b92f54682d87871`。包含该版本的 TP 返回显示恢复修复。正式发布标签为 `v0.4.2+fabric.26.3.15`。

## 四麻 AI

四麻空位和主动离座接管改为电将算法。初级采用 `@kobalab/majiang-ai` 的历史策略 `0002`，中级采用 `0202`，高级采用当前策略；固定 AI 版本 `1.3.0`、core 版本 `1.3.4`。这是 Mod 定义的策略档位，不是电将官方段位，也未宣称达到真人平台的某个段位。

初级按向听数及理论进张选牌；中级增加已见牌、可鸣有役进张和基础防守；高级使用当前电将的期望值、危险度与鸣牌判断。三个档位均只取得自己的手牌与公开局面，不能读取其他人的暗牌、里宝牌或牌山顺序。Mod 原规则引擎仍决定合法动作、和牌及计分。

三麻继续使用原项目 BOT，菜单明确提示难度仅在四麻生效。

## 安装和设置

1. 在服务端安装 Node.js 22 或更新版本，并让运行 Minecraft 的账号能执行 `node --version`。玩家客户端无需安装 Node.js 或模组。
2. 停服并备份存档后，用本次 JAR 替换旧麻将 JAR。现有 `26.3.14` 完整资源包可继续使用。
3. 扳手右键桌子中央或 `/mahjong menu` 打开设置。点击“默认四麻 AI”循环初级／中级／高级；底行四个座位按钮可分别选择“跟随默认／初级／中级／高级”。默认中级，开局后锁定修改。
4. 使用 `/mahjong leave` 离座，机器人使用该座位的难度接管；右键桌子或 `/mahjong join` 接回原座位。牌局、手牌、点数和原座位保留沿用现有逻辑。

AI 源码和 MIT 许可证已随 JAR 附带，不需要在服务器运行 `npm install`，运行中不访问远程 AI 服务。Node.js 本身不包含在 JAR 内。

默认难度和每座位覆盖值随牌桌存档、牌谱保存。旧存档没有难度字段时按中级及跟随默认载入；未知字段值按默认处理。AI 子进程的运行状态不写入存档，载入当前可见局面后重新计算。

## 运行与维护

Node.js 在后台工作线程中以常驻本地进程运行，通过标准输入输出交换 JSON。游戏主线程不等待进程启动或思考。返回结果只可选择当前合法行动；玩家接回座位、换局、牌桌卸载或游戏结束后，旧计算结果失效。并发和任务队列设有上限，服务端停止时关闭进程。

Node.js 不可执行、计算超时、返回异常或队列繁忙时使用合法的轻量牌效策略，使牌局可以继续，并在服务器日志记录降级。这种情况下不会具有所选电将档位的完整策略能力。

Node.js 不在服务器 PATH 时，可设置环境变量 `RIICHI_AI_NODE` 为可执行文件的绝对路径，或在 Java 的 `-jar` 前加 `-Driichi.ai.node=绝对路径`。决策超时默认 1500 毫秒，可用 `-Driichi.ai.timeoutMillis=3000` 修改（范围 100～10000 毫秒）。默认最多两个 AI 工作进程、32 个排队任务。JAR 首次使用时自动将内嵌源码提取到服务端 `config/riichi-mahjong-ai/runtime/<内容哈希>/`；不会下载依赖。

## 验证结果

- 构建通过，11 组 Java 回归通过，其中两组新增 AI 信息边界及进程通信回归；另外 10 项 Node AI 测试通过。
- 实际 Minecraft 26.3 隔离服通过 14 项 AI 集成检查，包含真实设置菜单的无网络操作、旧／非法 NBT、三麻保留原 BOT、读档、主动离座接管、原座位接回及过期任务失效。
- 三档 AI 完成 14 次真实引擎决策，牌局接受 12 次弃牌；该次运行没有发生超时或回退。
- 缺失 Node、非法索引、错误请求 ID、非整数索引、畸形 JSON、超时及过期回复分别在独立 JVM 中验证。停服后两个工作进程均结束。

菜单检查执行真实菜单构建和点击处理，但没有连接可见客户端做截图验收。高级策略仅根据各家自己的弃牌确定安全牌；原规则库没有保存全局弃牌时序和历史摸切信息，因此不推断“立直后他家打出”的额外安全牌。算法档位尚未通过大规模同牌山对战标定强度顺序；固定场景回归不等于完整多人实战或大量并发牌桌验收。完整证据见交付的 `verification.json`。

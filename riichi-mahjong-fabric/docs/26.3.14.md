# 0.4.2+fabric.26.3.14 · TP 返回后麻将桌显示恢复

修复玩家 TP 到远处再返回后看不见麻将桌的问题。此次只更新服务端显示生命周期管理，模型、材质和资源包内容没有变化，现有资源包可继续使用。发布附件 `TimoryResource-26.3.zip` 与 `26.3.13` 完全一致。

## 修复内容

麻将桌通过 Polymer 虚拟显示实体展示。区块卸载时，Polymer 会销毁显示实体的区块附件；旧版只判断区块和方块状态，可能继续保留附件已经失效的显示缓存，返回时也就无法重新发送完整桌面。另外，Minecraft 26.3 在更换玩家观察范围时先执行移除旧区块，再保存新范围；Polymer 0.18.7 的移除回调可能读到旧范围而保留观察关系，区块持续加载时尤其容易留下过期追踪。

- 每 tick 同时检查附件是否存在、是否已移除，以及附件关联的区块是否正是当前 `LevelChunk` 对象。失效时销毁旧显示，再依据当前方块重新建立显示。
- 每 tick 使用 Polymer 的区块观察者同步 API 核对当前观察范围及区块发送状态，移除离开的玩家、重新接入返回玩家；已在观察的玩家不会反复收到重建。
- 区块卸载时清理该区块的显示缓存、本人手牌、BossBar、碰撞注册及待处理请求，避免旧视图留在下一次加载中。
- 异步加载事件可能早于区块可访问的时刻。显示请求在区块暂不可取时最多重试 200 tick，重复请求会刷新期限，卸载会取消请求。重试只使用 `getChunkNow` 检查，不会为了显示而同步加载区块。
- 使用已经取得的 `LevelChunk` 创建区块附件，避免创建附件时再次同步取得区块。来自异步发送路径的显示请求统一调度到服务端线程处理。

恢复仅重建显示，不重新创建牌局驱动器，不改轮次、手牌、座位或分数。有效视图收到重复请求时继续复用，不会因重复发送而重建整桌。

## 已完成验证

本机环境为 Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.163.0、Java 25。

- `26.3.14` 构建通过，9 组主回归和 9 项通用服务器集成检查通过。
- 对照检查在隔离服务器销毁桌面的区块附件、保留可访问区块及原牌局。旧版 `26.3.13` 无法恢复桌体；客户端只剩 14 张本人手牌，桌体显示数为 0。新版恢复有效的区块附件和完整桌面显示。
- 新版恢复后核对牌局驱动器、当前轮次、手牌及分数，确认显示恢复没有重置牌局。
- 异步待处理请求检查确认：暂不可访问的区块会保留重试请求，检查过程没有同步加载区块。

## 原版客户端 TP 验收

使用正常运行的隔离服务器与原版 26.3 客户端完成 5 次往返：牌局玩家 3 次（区块持续加载时远距离 TP、往返下界、区块实际卸载后返回），旁观者 2 次（区块持续加载时远距离 TP、往返下界）。每个离开前、远离及返回阶段采集 3 次客户端实际实体，合计 36 次采样；服务端同时记录观察者数量、当前区块可访问性及真实维度。

全部通过：远离后观察者数及原桌显示数均为 0；返回后恰好 1 个桌体，四家手牌及文字恢复，实体 ID 在稳态采样间保持稳定，没有重叠或重复显示。牌局玩家看到 14 张本人牌面，其他玩家的手牌保持牌背；旁观者看到全部手牌牌背。区块实际卸载时旧视图已移除，返回后重新挂接至当前区块。对比坐标时允许原版移动数据包的 1/4096 格量化误差。

返回后的客户端截图已复核。测试汇总及最终 JAR SHA-256 见 Release 附件 `verification.json`，附件校验值见 `SHA256SUMS.txt`。原始客户端采样及截图同时保留在本地交付目录 `delivery/26.3.14/verification/`。

以上验证使用隔离测试服务器，测试探针及集成 addon 不包含在生产 JAR 中。固定场景验证不代表遍历整场多人牌局或所有其他模组组合。

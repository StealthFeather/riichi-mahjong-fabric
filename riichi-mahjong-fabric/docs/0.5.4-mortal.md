# Timory Mahjong 0.5.4 Mortal

本分支基于 0.5.4-beta.1。雀魂、天凤和 M-League 三种规则的四人标准牌桌会自动启用 Mortal，均支持东风场及半庄。牌桌负责判定合法动作、点数和连庄。三麻、川麻、WRC、公式战及开启换三张、赖子或血战的牌桌使用原有机器人。

## 服务端安装

安装包适用于 Linux x86_64（glibc 2.28+）、CPython 3.12，系统需提供 `venv`。沿用 0.5.4-beta.1 的客户端资源包。将构建产物 `timory-mahjong-0.5.4-mortal.jar` 放入服务端 `mods/` 并替换原版麻将模组。原有电将和牌谱分析仍使用 Node.js 22+。

将 `mortal-worker-0.5.4-mortal.zip` 解压到服务器工作目录，然后在该目录运行：

```sh
python3.12 mortal/install.py
```

使用源码安装时，将命令中的 `mortal/install.py` 换成源码目录里的 `riichi-mahjong-fabric/ai/mortal/install.py`。脚本下载并校验固定版本的社区 ONNX 权重、libriichi 和 Python 依赖，然后用真实模型检查弃牌、赤牌、立直和鸣牌。成功后可启动服务器。对局期间模型在本机 CPU 上运行。

默认程序路径为 `config/riichi-mahjong-ai/mortal/worker`。自定义安装目录时，把可执行文件的绝对路径写入服务端环境变量 `RIICHI_MORTAL_WORKER`。每次决策的默认期限为 5 秒，可用 JVM 参数 `-Driichi.mortal.timeoutMillis=5000` 调整。

## 对局行为

- Mortal 只读取该座位的手牌、摸牌和公开动作。玩家中途离座或服务器读档时，机器人按本手记录恢复视角。
- 若旧存档缺少完整的本手记录、模型离线或决策超时，由该座位的备用电将出牌。座次菜单中可调整备用电将的难度，Mortal 使用同一份模型。
- 这六种赛制中，杠后从岭上补牌会把活牌山末尾一张移入王牌。河底最后一张弃牌仍可荣和，不能吃、碰或杠。
- 模型使用天凤数据训练。东风场会调整模型看到的剩余局程并保留真实场风和风牌役。雀魂、M-League 和东风场的打牌强度未单独评测。
- 牌谱分析和玩家弃牌一致率继续使用 0.5.4-beta.1 的计算方式。

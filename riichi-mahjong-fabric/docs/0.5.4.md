# Timory Mahjong 0.5.4

本正式版包含 0.5.4-beta.1 的牌桌与宝牌更新，并加入 Mortal 实战和牌谱评分。雀魂、天凤和 M-League 三种规则的四人标准牌桌会自动启用 Mortal，均支持东风场及半庄。牌桌负责判定合法动作、点数和连庄。三麻、川麻、WRC、公式战及开启换三张、赖子或血战的牌桌使用原有机器人。

## 服务端安装

安装包适用于 Linux x86_64（glibc 2.28+）、CPython 3.12，系统需提供 `venv`。沿用 0.5.4-beta.1 的客户端资源包。将构建产物 `timory-mahjong-0.5.4.jar` 放入服务端 `mods/` 并替换原版麻将模组。其他四人规则的电将与回放分析使用 Node.js 22+。

将 `mortal-worker-0.5.4.zip` 解压到服务器工作目录，然后在该目录运行：

```sh
python3.12 mortal/install.py
```

使用源码安装时，将命令中的 `mortal/install.py` 换成源码目录里的 `riichi-mahjong-fabric/ai/mortal/install.py`。脚本下载并校验固定版本的社区 ONNX 权重、libriichi 和 Python 依赖，然后用真实模型检查弃牌、赤牌、立直、鸣牌和回放权重。成功后可启动服务器。对局期间模型在本机 CPU 上运行。

默认程序路径为 `config/riichi-mahjong-ai/mortal/worker`。自定义安装目录时，把可执行文件的绝对路径写入服务端环境变量 `RIICHI_MORTAL_WORKER`。实战决策默认限时 5 秒，可用 JVM 参数 `-Driichi.mortal.timeoutMillis=5000` 调整。回放使用独立推理进程，单次请求默认限时 10 秒，对应参数为 `-Driichi.replay.analysisTimeoutMillis=10000`。

## 对局行为

- Mortal 只读取该座位的手牌、摸牌和公开动作。玩家中途离座或服务器读档时，机器人按本手记录恢复视角。
- 若旧存档缺少完整的本手记录、模型离线或决策超时，由该座位的备用电将出牌。座次菜单中可调整备用电将的难度，Mortal 使用同一份模型。
- 这六种赛制中，杠后从岭上补牌会把活牌山末尾一张移入王牌。河底最后一张弃牌仍可荣和，不能吃、碰或杠。
- 模型使用天凤数据训练。东风场会调整模型看到的剩余局程并保留真实场风和风牌役。雀魂、M-League 和东风场的打牌强度未单独评测。

## 牌谱回放评分

在「我的牌谱」点本场的发财启用分析，或在回放控制面板开启「Mortal 分析」。回放按牌谱里记录的规则选择引擎。雀魂、天凤、M-League 的标准四人东风场和半庄均采用本地 Mortal v4。分析按当时所选座位的手牌及公开信息逐步重建局面，打开全手牌展示也使用同一视角评分。

Mortal 为合法打法给出 Q 值，回放以温度 1 的 softmax 换算相对权重。同一牌种的赤五、普通五、普通弃牌和立直宣言牌取其中最高的估值，再与其他可弃牌种比较。手牌上显示候选弃牌权重，有多个操作按钮时，最多标注权重最高的三个按钮。权重表示模型在该局面下的打法偏好。

每次实际弃牌的**一致性分**为 `100 × 实际弃牌权重 ÷ 最高弃牌权重`。例如最高权重 40%、实际所选牌种 30%，该次得 75 分。各席的单局分和整场分都按实际可评分的弃牌逐次平均，只在显示汇总时取整。回放重算时会忽略旧版本的评分缓存。

早期牌谱若缺少同牌摸切标记，按摸切重建该步。缺少本手起始记录或超出标准牌山范围的局面会显示无法还原，并从均分中剔除。推理进程暂不可用时，可在恢复后重新启用分析。

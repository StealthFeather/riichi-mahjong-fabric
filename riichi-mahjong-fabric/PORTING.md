# Riichi Mahjong Fabric 服务端移植

目标环境为 Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.163.0、Java 25。客户端使用原版 26.3，接受合并后的 TimoryResource，不安装此 Mod。

## 来源

- 原项目：https://github.com/caxapexac/MinecraftRiichiMahjong
- 固定提交：`fe469836ed461d44998819dd3004c8dea01f5be0`，原版本 0.4.2。
- `upstream/` 是完整原始快照；原项目及 Mahjong4j 许可随发布保留。
- `src/main/java/com/riichimahjong` 移植原项目服务端模块；`fabric/` 替代 NeoForge 注册、客户端渲染、菜单和网络交互。
- `themahjong` 基于原始快照编译，构建时通过 `rules-patches.cjs` 修正供托提交后的旧状态覆盖、已接受响应的过期候选，以及 BOT 接管时的响应保留；`upstream/` 不修改。未使用旧 Timory 自制规则或旧模型。
- 原始模型、纹理、音效完整保留。`items/bridge` 是直接引用原始方块模型的原版显示入口；唯一补充的牌背模型只引用原始空白牌面与牌壳。

## 内容与操作

`/mahjong` 查看操作，管理员 `/mahjong give` 打开原项目物品目录。

放置原麻将桌后，直接右键桌边、桌角或桌外的座位文字入座，聊天栏会明确提示成功或失败，座位文字显示当前玩家。普通右键中央自动选择最近空位；也可 `/mahjong join` 入座，或 `/mahjong join <1..4>` 指定东、南、西、北座位。潜行右键中央开局，四麻空位使用所选难度的电将 AI，三麻沿用原项目 BOT。牌桌扩大为以中心方块正中为中心的 3×3 格，麻将牌的三维尺寸、排列间距及单张 interaction 同步放大 1.5 倍。桌面显示随庄家轮转的门风和当前出牌标记，以及已缴立直棒和结转供托；场次、分数和结果显示在本人 BossBar。右键自己的单张手牌出牌。立直、吃、碰、杠、荣和、自摸、拔北等通过经验条上方提示和本人面前的可点击按钮操作；按钮随窗口过期或响应提交而移除，不再写入聊天历史。立直选中后绿色箭头标记合法弃牌。主动离座使用 `/mahjong leave`，点击桌子、牌或按钮不会离座。离开后 BOT 暂代；普通右键桌子或 `/mahjong join` 优先接回原座位，保留当前手牌、分数与轮次。原座位为离开的玩家保留，座位保留随当前比赛存档保存。扳手右键中央或 `/mahjong menu` 打开设置，可选择雀魂四麻、天凤四麻、WRC 四麻、雀魂三麻、天凤三麻、座位和供牌方式。牌桌库存通过四页原版箱子菜单访问。结算后点击中央继续。

牌谱与预设练习牌谱、单人配对麻将、麻将祭坛、役发电机与自动点击器、牌食物与条牌燃料、立直棒投射物、画作、原始配方和进度均导入。

麻将进度的页签、役种标题及全部达成说明提供简体中文翻译，收录于合并后的 TimoryResource。进度背景使用 26.3 的纹理资源标识格式，避免旧版路径重复添加前缀和后缀导致黑紫方格。翻译覆盖文件单独保存在 `resource-overrides/`，原始快照保持不变。

单人麻将右键单张牌配对，右键底座执行原项目提示操作，清空后潜行空手右键中央重开。Fabric 物品管道可以输入铁锭、金锭、钻石执行原项目自动提示，液体接口输出液态经验（81000 单位为一桶）。役发电机保留原项目发电逻辑，存在 Team Reborn Energy API 时接入其侧面能源接口并向相邻接收器推送；没有该 API 时保留内部储能。

`26.3.18` 修复按钮空点默认跳过和摸切，并在 `/mahjong menu` 加入桌主可用的“重置牌桌”。重置须再次确认；确认后结束牌局、清除比分与供托并释放座位，保留库存、规则和 AI 设置。详见 [本版说明](docs/26.3.18.md)。

## 四麻 AI

`26.3.15` 基于正式版 `26.3.14` 添加四麻三档电将 AI。服务器需可执行 Node.js 22+；AI 与 core 的固定版本源码和 MIT 许可随 JAR 内嵌，无需 npm 安装或外部 AI 网络服务。默认中级，牌桌设置可配置各座位覆盖，开局后锁定；配置随存档保存，旧存档缺省中级。三麻仍使用原 BOT。后台计算结果经当前合法动作表校验，错误或超时回退轻量策略。详见 [四麻 AI 说明](docs/26.3.15.md)。

## 数据隔离

- 完整牌局与洗牌状态只保存在服务端。麻将桌没有公开更新 NBT，也没有自定义客户端牌局同步包。
- 公共牌桌渲染器仅接收经过筛选的公开投影：暗牌张数、公开牌、点数、当前结果；不接收暗牌身份、牌山身份、随机种子或合法动作集合。
- 暗牌牌面和每张牌的 interaction 放在使用 ManualAttachment 的私有虚拟实体容器中，不参与区块自动跟踪，只登记所属玩家，并逐实体再次核对可见玩家。
- 其他玩家和旁观者只收到统一空白牌背。摸牌不放入真实主手，避免装备包泄露。
- 操作使用本人可见的 interaction；服务端再次核对玩家身份、座位、距离、牌局状态和当前合法动作。旧版聊天令牌不再创建，已有令牌命令一律返回过期。
- 自定义物品的发送内容使用白名单，不携带源物品的自定义数据、方块实体数据或完整牌局。牌谱只在服务端保存，物品内仅持有不公开的随机索引。

## 原版客户端限制

原 NeoForge 客户端的 FOV 摄像机调整、渲染编辑器、悬停描边与专用 GUI 不能直接在未修改客户端执行。此移植以显示实体、interaction、ActionBar 提示、本人按钮和原版容器界面替代。自定义流体在原版客户端使用水的物理表现；原液体材质仍保留在资源包。方块显示使用原始模型，麻将桌与单人麻将底座使用空气占位，每桌仅一个虚拟潜影贝及一个零尺寸 marker 锚点。麻将桌模型水平为 3×3 格，潜影贝缩放为 3，顶面对齐台面；服务端玩家移动使用相同的闭壳包围盒，并以空气替代旧桌脚、桌沿形状的玩家碰撞，避免两端高度冲突导致反复下落。碰撞按区块索引，不同步加载区块，牌桌拆除、区块卸载或服务器关闭时随显示容器移除。多余立方体高度位于桌下，因此悬空桌下方的碰撞仍是近似。单人麻将保留 2×2 格。潜影贝通过原始元数据访问器明确写入 Invisible、NoAI、Silent、NoGravity、闭壳与向下附着状态，不生成真实生物，其余方块保留原版占位，不能声明与原客户端逐像素、逐碰撞完全一致。

## 构建与验收

将 `riichi-mahjong-fabric/` 放在准备好的工作区根目录，进入该目录执行 `node resources.cjs`、`node build.cjs` 和 `node test.cjs`。构建脚本使用已准备的 Java 25、Minecraft 26.3 和 Polymer 依赖。发布入口为 `node package.cjs`，会重新生成工作区 deploy/ 下的发布文件。

`prepare.cjs` 和 `adapt.cjs` 是首次导入时的迁移辅助记录，不应在已移植源码上重新运行。可直接修改当前 `src` 并重新构建。发布同时提供完整源码，便于替换规则库与自行修改。

0.4.2+fabric.26.3.8 已进行编译与定向回归：多家连续立直、宣言牌被碰时供托保留及后续立直、各家独立操作按钮、已响应候选失效、BOT 接管、三麻/四麻鸣牌方位和 2×2 坐标/文字朝向。执行 `node test.cjs` 可重现检查，报告位于 `build/verification.json`，打包时校验报告与 JAR 哈希一致。原始“第一家立直后其他家无法立直”在纯规则场景未复现，相关交互仍需客户端复核；完整联机牌局、网络协议与客户端视觉未实测。本版新增牌模型射线命中与原座位重返回归。完整变更见 `docs/26.3.8.md`，上一版记录保留在 `docs/26.3.7.md`。
